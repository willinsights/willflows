## Changes
- Signer preserves `${workspace}/${taskId}/${timestamp}_${uuid}.${extension}`. Omitted task yields literal `undefined`, explicit null yields `null`, preserving the legacy contract. The signed receipt, not the key alone, binds uploader, resolved workspace/project/task, key, filename/size and replacement ID. Five-segment keys already persisted remain readable.
- Receipt JSON is encoded/decoded as UTF-8 before/after base64; HMAC SHA-256 authenticates the encoded body. Existing managed service credential and domain prefix remain server-only; no new secret or client signing capability. Key rotation invalidates outstanding receipts; no previous-key fallback.
- Presigned PUT lasts 120 minutes, receipt 240 minutes, proposed client XHR timeout 90 minutes. These are candidate engineering defaults, not a guarantee against browser suspension or network stalls. Receipt is verified before object HEAD/Stream/writes. The Stream-copy GET window remains 60 minutes as before; copy/provider performance is not verified offline.
- Expired authentic receipt returns HTTP 409, `UPLOAD_EXPIRED`, `restartUpload: true`, before any object access/write. Client shows a new-upload instruction and requires a new signer response/new key/new PUT. No renewal from client-supplied keys, unsigned fallback, automatic processing retry or uncertain-write replay. A partially/completely uploaded expired object is not automatically deleted; orphan lifecycle/accounting remains a separate issue.
- Strict processor persists the authenticated uploader together with resolved project/task on insert/replacement, checks confirmed replacement write and existing-key compare condition. Nullable legacy project is resolved through its task. Existing ID/version-number behavior is otherwise unchanged.
- Review queries nullable-project versions inside the token workspace, resolves actual task/project, and retains only token-covered versions. Comments/approvals are fetched by validated version IDs, not nullable project fields; associations still must be coherent. Comment deletion accepts absent legacy project/task when the authorized version provides the context. No broad project fallback for task tokens.
- Active role checks, download authorization, token activity/expiry and coherent persisted legacy-key validation remain in force. No historical rows are changed. Existing project-wide links remain project-wide; task-only links derive the project.
