# WillFlow 2.0 · beta em ambiente real (18/11/2026)

## Objetivo

O proprietário pretende experimentar desde já o WillFlow 2.0 com dados reais, sem abandonar o Lovable Cloud nem modificar massivamente a aplicação em produção. Esta entrega é um **modo opt-in para testar uma experiência nova sobre os mesmos dados**, não o sistema integralmente reconstruído.

## Acesso

Após login no WillFlow, como administrador do workspace, o atalho `Experimentar WillFlow 2.0` aparece na barra lateral (desktop) e `2.0` no cabeçalho móvel. Rota protegida: `/app/demo-v2`.

- Contadores reais de projetos, clientes, vídeos ativos, pagamentos, faturação, contratos e armazenamento. Estes são valores lidos através das políticas RLS.
- Cards com detalhes e separação por módulo, pesquisa local dos registos carregados e botão para carregar mais 100 até ao limite de 2.000 por módulo, sem guardar valores no browser.
- Acesso aos módulos produtivos existentes para trabalhar realmente em projetos, edição, financeiro, calendário, chat e equipa. As operações desses módulos continuam sujeitas às permissões e comportamentos da aplicação atual.
- O novo painel de visão geral é estritamente **read-only**; não faz SQL de escrita, upload, cobranças, notificações, triggers ou novas migrations.
- A demo pública estática continua independente e exclusivamente fictícia.

## Proteções

1. É necessário utilizador autenticado; a página está dentro do `ProtectedRoute` existente.
2. Verificação local de associação ativa ao workspace e `role === 'admin'`; RLS de Supabase/Lovable Cloud verifica cada SELECT.
3. Cada pedido SQL é filtrado pelo `workspace_id` da sessão. Os registos do workspace anterior são removidos ao trocar de workspace e respostas tardias são ignoradas.
4. Não se usam chaves `service_role` nem segredos administrativos no frontend.
5. Para regressar, usar o botão `App atual` ou navegar pelo menu normal. Desativação é revertível removendo o atalho e a rota numa atualização de frontend; sem rollback de BD.

## O que falta para a versão completa

O painel beta não substitui o conjunto de funcionalidades existentes. O PR #2 de vídeo/armazenamento **continua sem aplicação em produção**, porque falta reconciliar 1 contador divergente, inventariar a existência física de objetos R2, validar condicionais CopyObject na conta real, comprovar restore num ambiente separado e fazer uma transição controlada dos jobs legados. Também não altera o motor financeiro, Stripe, contratos, faturação fiscal, permissões, preços ou notificações.

## Plano de publicação

- GitHub Actions: TypeScript, build, verificações de escopo admin/RLS, navegação mobile e ausência de escrita.
- Merge isolado deste frontend somente se CI passar.
- Confirmar sincronização do commit `main` com o Lovable e solicitar publicação.
- **Não afirmar que o novo deploy está visível** sem verificação independente da versão efetivamente servida.
- Teste manual do proprietário: login → `/app/demo-v2` → alternar módulos e abrir cards → navegar para um módulo atual e regressar. Testar em mobile e desktop.
- Registar eventuais erros de acesso/relação de colunas e corrigir em PR pequeno, sem alterar a BD em produção.

## Resposta a incidentes

Se houver ecrã em branco, erro de permissão, valores inconsistentes ou problemas de navegação: interromper o teste da página V2, regressar à app atual e registar o erro. Não executar reparações diretas de quotas ou dados reais a partir do painel. Uma reversão do frontend pode ser feita via commit revert no GitHub e novo deploy Lovable; **não envolve restore da BD**.
